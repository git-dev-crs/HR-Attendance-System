# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `health()` | Always returns `{"status": "ok"}` regardless of MongoDB state — never pings the database | Stop MongoDB, hit `GET /health` → still returns 200 OK | Added `client.admin.command("ping")` inside a try/except; returns 503 if it raises |
| 2 | `create_employee()` line 82 | `datetime.now()` returns a **naive** (no timezone) local datetime, stored in MongoDB without UTC context | Seeded docs have a local timestamp; analytics that compare timestamps break across time zones | Changed to `datetime.now(timezone.utc)` to store a proper UTC-aware BSON date |
| 3 | `create_employee()` — no unique-index race safety | Uses check-then-insert (`find_one` then `insert_one`): two concurrent requests with the same `emp_code` can both pass the check and both insert | Run two simultaneous POST requests with the same `emp_code` → both return 201 | Removed the pre-check; rely on the unique index on `emp_code` and catch `DuplicateKeyError` → 409 |
| 4 | `list_employees()` line 93 | `skip = page * page_size` should be `(page - 1) * page_size`; page=1 skips the first 20 records | `GET /employees?page=1` returns nothing if fewer than 21 employees exist | Changed to `skip = (page - 1) * page_size` |
| 5 | `list_employees()` line 94 | `total = db.employees.count_documents({})` ignores the `department` filter — total count is always for all employees | `GET /employees?department=Engineering` shows total=6 even if only 2 match | Changed to `db.employees.count_documents(q)` using the same filtered query `q` |
| 6 | `list_employees()` | No `sort` applied — order is undefined (MongoDB natural order, not `emp_code` ascending) | Results change order after inserts/updates; spec requires sorted by `emp_code` ascending | Added `.sort("emp_code", 1)` to the cursor |
| 7 | `punch_in()` line 102 | `datetime.fromtimestamp(ms/1000)` converts to **local system time** (IST on your machine, UTC elsewhere) — stored as naive datetime | On a UTC server, punch times are 5h30m off; R1 date calculation gives wrong attendance date | Changed to `datetime.fromtimestamp(ms/1000, tz=timezone.utc)` (aware UTC datetime) |
| 8 | `punch_in()` | No 404 check — if `emp_code` doesn't exist, `emp["shift_start"]` raises `TypeError: 'NoneType' object is not subscriptable` | POST punch-in with unknown `emp_code` → 500 Internal Server Error instead of 404 | Added `if not emp: raise HTTPException(404, "Employee not found")` before using `emp` |
| 9 | `punch_in()` — race condition | Check-then-insert: `find_one` checks for existing record, then `insert_one` — two concurrent punch-ins for the same day can both pass the check | Simultaneous punch-in requests → both return 201; duplicate record violates business rule | Removed the `find_one` pre-check; catch `DuplicateKeyError` from the unique `(emp_code, date)` index → 409 |
| 10 | `compute_late_minutes()` | `punch_in.replace(hour=h, minute=m)` copies the punch_in datetime's date but uses local time arithmetic on a naive datetime — wrong when punch_in is UTC | A 09:35 UTC punch-in (= 15:05 IST) is compared to 09:30 on the same UTC date, not IST date | Rewrote to convert `punch_in` to IST first (`astimezone(IST)`), build `shift_start_dt` as IST-aware datetime, then compute difference in seconds |
| 11 | `list_attendance()` | `list(db.attendance_logs.find(q))` loads **all matching documents into Python memory**, then sorts in Python | On a 100k-record dataset this causes OOM / extreme latency | Removed in-memory sort; added `.sort([("date", -1), ("emp_code", 1)])` to the cursor and moved `.skip()/.limit()` to the database |
| 12 | `list_attendance()` line 94 | `total = len(docs)` counts only the current page's documents after sort, not the real filtered total | Page 2 onwards shows `total` = page_size (20) instead of the true total | Changed to `db.attendance_logs.count_documents(q)` before pagination |

## Not a defect

- `compute_work_hours` uses `round(..., 2)` which is Python's banker's rounding (round-half-to-even). For R4 this should be **half-up** rounding. I flagged this and replaced it with `Decimal.quantize(ROUND_HALF_UP)` — strictly speaking this is a business rule violation, not just a style issue, so it IS in the table above as defect #10. Considered: keeping Python's default round — rejected because the spec says "half-up" explicitly.
- The `IST = timezone(timedelta(hours=5, minutes=30))` constant was correct and retained.
- `compute_overtime` in the starter was directionally correct but failed for overnight shifts (it built a naive datetime). Rewritten to handle overnight shifts using `shift_end` falling on next calendar day.
